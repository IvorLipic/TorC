What we found when we checked

Before animating anything, the implementation was traced in source and exercised with small programs, then compared against hand-derived math and central finite differences. The core library was not modified. Full text: docs/autograd-audit/implementation-contract.md.

Behavior worth knowing observed

  • The root of a backward() never gets .grad(); the seed 1.0 is internal. The animations show it as a seed.
  • Only the root's tape is cleared after backward(). A second backward() on the same root is a silent no-op; gradients accumulate across different roots until zero_grad().
  • backward() on an intermediate node permanently cuts the graph above it for later losses (no retain_graph).
  • The graph holds raw, non-owning pointers: every tracked Variable must outlive backward(); destroyed ancestors make backward throw TorcError. Calling an nn::Module again invalidates the previous forward's graph.
  • relu'(0) = 0; for max/min ties the gradient goes to the first element only.

Suspected defects bug

D1 · slice backward scatters to wrong indices (medium–high, reproduced, probably common: any narrower 2-D crop). Strides are computed from the sliced shape instead of the input shape, so any 2-D crop that is narrower than the input is affected, even without an offset (src/autograd.cpp ≈ 743–750). For a = [[1,2,3],[4,5,6]], slice(a, {{0,2},{1,3}}) then sum().backward() gives [0 1 1 1 1 0]; math says [0 1 1 0 1 1]. Cropping {{0,2},{0,2}} gives [1 1 1 1 0 0] instead of [1 1 0 1 1 0]. Existing tests only slice row 0, so they pass.
D2 · negative axis in autograd reductions (low–medium, reproduced). Forward normalises it; the autograd wrappers for sum/mean/max/min(x, axis) do not. sum(x, -1) yields an all-zero gradient and max(x, -1) reads out of bounds.

Minor: -0 can appear in gradients; Module::parameters() order is unspecified (3 optimizer tests rely on it and fail); docs say the grad-mode flag is process-global but it is thread_local; build_topo is recursive. These are reported, not fixed — changing core behavior needs the owner's decision. The scenes avoid every affected feature.

What was verified math

Central finite differences (h = 0.01, tolerance 0.01) matched autograd for exp, log, sqrt, relu, sigmoid, softmax (all variants), neg, sub, mul, div, sum/mean (non-negative axes), max/min, transpose, reshape, matmul, broadcasting add/mul, MSELoss and CrossEntropyLoss. slice failed (D1). The three scenes on the home page carry their own finite-difference check, recomputed on every run of the generator.

Not verified

Conv2d and data-loader paths beyond the existing tests, thread-safety, very deep graphs (recursive topological sort), and the 3 failing optimizer tests under GCC ≥ 14 (only clang 18 was used).
