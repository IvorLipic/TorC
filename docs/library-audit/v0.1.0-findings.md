# TorC v0.1.0: findings from writing the lessons

Library behaviour found while tracing the lessons on this branch. The site does not change the library (`main` is library only),
so these are notes for a later fix there. Each entry names the trace or probe that shows it.

## `nn::MSELoss` does not check shapes, and its gradient does not match the loss it reports
`MSELoss::forward` (`src/nn/losses.cpp`) computes `input.data().sub(target.data())`, which broadcasts. A prediction of shape
(B, 1) against targets of shape (B), the most common mistake, gives a (B, B) difference and no error. The loss is the mean over
B·B values. The backward pass divides by `input.numel()` (B), not by B·B, so the gradient is B times the derivative of the loss
it reports. Trace at v0.1.0: `site/data/losses.json` `mse_broadcast` (B = 3: loss 3.333 instead of 0.1667, gradient `2, -3, 1`).
At v0.1.0 the lesson Losses warned about it.

**Status on `main`: fixed.** PR #5 (`3566402`, merged 2026-10-14) made backward divide by the broadcast count, so the probe gave
`0.667, -1, 0.333`, the derivative of the reported loss, but it kept the broadcasting. PR #6 (`38785db`, merged 2026-10-29)
removes it: `MSELoss::forward` now throws `ShapeError` when the shapes differ, for example
`MSELoss input shape (3, 1) must match target shape (3)`. Same-shape losses and gradients are bit-identical to v0.1.0.
The site pins `38785db` since 2026-10-29. The trace entry is now `losses.json` `mse_mismatch` (the exception and its text), and
`linear.json` `mse-shapes` records the new text. The lesson Losses no longer mentions the problem (pedagogy review D6).

## `data::SyntheticRegression` fills only the first input column
With `num_features > 1`, the constructor writes `xs_.data()[i * num_features]` only, so every other column stays 0 and `y`
depends on column 0 alone. The lesson uses one feature. Source: `src/data.cpp`, `SyntheticRegression::SyntheticRegression`.

## The MNIST converter and `data::MNISTDataset` both divide by 255
`datasets/mnist/convert_to_csv.py` writes each pixel as `p / 255.0`, and `MNISTDataset` divides every pixel by 255 again
(`src/data.cpp`, `xs_.data()[...] = rows[i][j + 1] / 255.0f`). The examples therefore train on inputs between 0 and 1/255. They
still learn, because the first layer's weights grow, but the inputs are not what the code intends. The site's
`tools/trace/fetch_mnist.sh` writes raw pixels 0..255. A fix on `main`: write the raw pixel in the converter.

## By design, but easy to miss
- `data::DataLoader` never resets itself. Without `reset()`, every epoch after the first has no batches and no error
  (`site/data/training.json` `no_reset`). The lesson The training loop says so.
- `optim::SGD`, `Adam` and `AdamW` skip a parameter whose `has_grad()` is false, so AdamW does not decay it
  (`site/data/optimizers.json` `decay`). The lesson Better optimizers says so.
